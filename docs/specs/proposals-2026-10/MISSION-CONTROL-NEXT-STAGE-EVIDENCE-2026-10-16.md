All sources below were opened from primary official documentation on **2026-10-16 UTC**. Public/beta/preview/GA labels are copied only where the source explicitly established them. ### Verified corrections

- **OpenAI Decisions API exists**, in public beta, at `POST /v1/decisions`; the current guide supports only `gpt-6-luna`. It returns estimated predicates, fixed choices, and rubric scores. Typed outputs and confidence do not establish factual correctness. [O1]
- **OpenAI Agents API exists**, in public beta, and is distinct from Agents SDK and Responses. OpenAI runs a managed Codex harness; the caller selects hosted, self-hosted, or no sandbox. [O2–O4]
- **Gemini 4 Argon exists** in current official documentation, model ID `gemini-4-argon`. Argon is a model, not an alternate name for an orchestration API. Interactions is documented as GA since June 2026. [G1]
- **Gemini webhooks exist** for batch and interaction events. A missing webhook mention in the background/deep-research guide is not evidence of absent support. [G5]
- **Jev direct and Gateway routes both exist**. Current Gateway docs explicitly retain `/v1/evaluate` with Boolean probability questions, as used in the repository, in addition to the TypeSafe-compatible route. Do not infer a migration requirement from the newer naming. [J1–J5]
- Current Interfaze reference lists `interfaze-1` and `interfaze-1.1-lite`. A repository using `interfaze-beta` needs compatibility validation; the current model table does not establish that older ID remains accepted. [I1]

## Contract implications (design inferences, not provider guarantees)

1. Capability keys should be scoped to **provider + product + endpoint + model/version + execution mode**, not provider alone: `hosted_agent_harness`, `hosted_tool`, `caller_tool`, `background_job`, `batch_job`, `client_async`, `webhook`, and `prompt_cache` are different capabilities.
2. Persist provider resource ID, native status, caller attempt/idempotency key, requested/resolved model, source/region/retention policy, and usage/cost separately from Mission Control's own task success state. Provider idle/completed means execution state, not acceptance-test success.
3. Webhooks are wake-ups: verify signature, deduplicate, acknowledge quickly, fetch authoritative resource, reconcile lost/out-of-order events, and preserve polling fallback. Thin provider payloads should not directly authorize side effects.
4. Keep constrained decision results separate from prose generation: native probability, derived confidence, unavailable metadata, refusal, malformed output, and no-answer must remain distinguishable. Validate thresholds on representative labeled data; do not promise zero hallucinations.
5. Maintain a verified-doc support registry with access date and unknown/conflicting states. No schema or platform name search miss is proof that the product does not exist. Current named products here have affirmative official evidence.
