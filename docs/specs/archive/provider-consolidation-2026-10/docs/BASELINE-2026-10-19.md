## 1. The vocabulary of a running mission (as built)

```text
Run ─┬─ Activation (one per program node; repetition_ordinal)          0003_execution.sql:82
     └─ Attempt (attempt_no, execution_generation)                      :118
          └─ HarnessExecution (lane_profile, generation, native ids)    :149, 0027:23-31
               └─ AgentSession (native_session_ref, predecessor)        :174
                    └─ SessionTurn (turn_no, started/ended frame)       :201, 0027:37-42
                         └─ ProviderFrame (arrival_ordinal)             0027:48-105
```

- A Goal Loop **iteration** is one executor operation plus one verifier operation; a Stage Graph
  **stage activation** is one operation. Both resolve to the chain above through the unit identity
  (`domain/graph_runtime/identities.py:147-164`).
- `provider_frame` carries `native_turn_ref` but no `turn_id`, iteration or stage column; a
  `session_turn` row exists only after its closing frame lands (`adapters/postgres/frames/identity.py:445-488`).
- Non-closing frames expire after 30 days and bodies are stored as digest + 8 KiB excerpt
  (`0027:113-127`). Transcripts are computed on read, capped at 50 000 frames
  (`application/frames/transcript.py:63`).
- Temporal history holds only orchestration decisions; Goal Directed and the operation workflow
  continue-as-new (`adapters/temporal/workflows/goal_directed.py:771-779`, `operation.py:728`), so
  **Postgres is the only point-in-time authority**.

## 3. Stage Graph workflow

- **DAG only; cycles are invalidation, not edges** (`domain/programs/interpreter.py:491-696`) [T].
  A cycle is triggered by the stage's own structured output `evaluation == "cycle"`
  (`adapters/temporal/workflows/stagegraph.py:842-881`), bounded by `max_cycles` and "objective must
  differ"; hitting the cap raises instead of producing a governed outcome (`interpreter.py:499-541`).
  Revisit Regions with `until/while/until_no_progress` are [D] (`workflow-types/01-STAGE_GRAPH.md:97-121`).
- **No nested Goal Loop**: a `goal_loop` child is lowered to one stage operation
  (`manifest_lowering.py:306-317`) [D for nesting]. An "infinite cycle" stage that feeds dependents
  therefore exists only as a model-triggered stage cycle, not as a goal-directed stage.
- **Dependent-stage transfer** [T, L on run k]: accepted output refs → frozen `StageInputBinding`
  (`interpreter.py:1137-1191`) → captured bytes under `inputs/<binding>/` (`pack_service.py:304-388`),
  digest-verified at placement (`application/agentic_components/placement.py:219-253`), schema-validated
  before admission. **Lost**: producer conversation, unregistered workspace edits (except by accident of
  lease reuse), non-schema prose, and for cycles `prior_result_refs`/`unmet_obligation_refs` (computed at
  `interpreter.py:562-583`, never delivered). Unresolvable model-invented refs degrade to zero-byte
  untrusted references instead of failing (`pack_service.py:749-766`).
- **Handoff from a cycling stage**: once per accepted result; dependents stay unresolved until admission
  and a cycle resets them to a new generation (`interpreter.py:432-447, 617-627`).

## 4. Sandbox and workspace

- Lease `reuse: none | within_run | within_session`, default `within_run`
  (`application/workspaces/policy.py:45-50, 111-136`): one worktree shared by every stage, iteration,
  executor **and verifier**.
- **Critical defect**: `outputs/` is only `mkdir(exist_ok=True)` (`placement.py:256-271`) and lanes
  collect everything under it (`adapters/claude/harness.py:372-381`). Run 2 runs h/i re-collected an
  upstream `diagnosis.json` at the patch stage [L]. By inference a session-lane verifier shares and
  re-collects the executor's outputs.
- Agent configuration (instructions, MCP, skills, plugins, subagents, hooks) is re-projected per
  harness-execution generation, idempotent and checked against `materialization_digest`
  (`adapters/claude/harness.py:505-556`) [T].
- **Runtime installation vs file writing**: Environment Kits' mission layer runs setup steps and probes
  toolchain versions but does not install base runtimes on local lanes
  (`domain/authoring/environment_kits.py:4-11`). Real package install exists only where the provider
  owns the image: `cursor_cloud` (Cursor environment `install`), `claude_managed` (`packages`),
  `codex_agents` (template packages). Deep Agents is explicitly unbound from kits
  (`application/environments/requirements.py:38,112`); its Docker sandbox is read-only, no network.
- Workspace snapshots are taken at **session end** only (`application/workspaces/snapshots.py`); a fork
  restores the newest released lease of the run (`adapters/postgres/lanes/workspace_leases.py:697-728`).

## 5. State retrieval, time travel and fork

- Fork path [T]: `POST /runs/{id}/snapshots` → `POST /runs/{id}/forks` → saga
  (`application/recovery/run_forks.py`) → seed (`fork_seed.py`). Stage Graph fork with reuse of
  unaffected work is proven offline.
- **Fork points**: current head only, at `stage_settled` or `goal_verifier_settled`
  (`0013:20`, `run_forks.py:505-509, 652-719`). **Snapshots are on demand**; nothing captures them at
  every boundary, so a past iteration is unforkable unless someone snapshotted it in time.
- **Cognition is never restored**: `cognitive_seed` is rejected (`domain/policies/forks.py:493-497`); a
  fork gets a `fork` Context Packet (workspace + optional instruction + Cursor-cloud-only 32 KiB
  conversation excerpt).
- **Read API**: transcript `since` is a lower bound only; no `until`, no filter by iteration/stage
  cycle/turn, no state-projection-as-of endpoint (`interfaces/http/transcript.py:228-310`).

## 6. Interventions, human control and mutation

- **Queue / add_context** [T]: durable `command_mailbox`, claimed at the next boundary into a mandatory
  `queued_instruction`.
- **Inject** [T, L runs b, c, d, j]: `cancel_and_replace` on every lane (`domain/execution/lane_turns.py:206-229`)
  except `codex_cloud`. Native mid-turn steering exists but is unused: Codex `turn/steer`, Managed Agents
  `user.message`, Agents API send.
- **Inject aimed at a finished node** lingers until run terminalization — neither applied nor refused
  (`application/execution/harness/inject.py:145-150`; `domain/policies/mailbox.py:64-66`) [L run k].
- **Artifact + file reference injection**: only `add_context` with `expand=materialize` at the next
  boundary (`pack_service.py:886-940`); the inject follow-up packet carries no files
  (`pack_service.py:956-957`). No mid-turn file push exists.
- **Pause** is boundary-only everywhere, yet Claude/Codex receipts say `pause_at_tool_gate`
  (`lane_turns.py:236-249`, `workflows/operation.py:366-382`); Codex `hold_approvals` has no caller.
- **In-memory state audit**: no correctness-bearing in-memory interrupt store was found. Approvals bind
  a Postgres Human Task and correlation **before** waiting; `asyncio.Event`s are wake hints
  (`application/execution/approvals_broker.py:165-343`). In-memory items that matter: Codex pause-hold
  state (moot, uncalled) and a process-local budget lock (`budget_controls.py:82`, unverified CAS cover).
  `InMemoryHumanTaskRepository` is test-only.
- **Approval timeout**: 300 s wait then `deny` + interrupt on local lanes
  (`application/execution/approvals.py:984-996`) [L run e]; hosted lanes leave the request pending
  (`hosted_tools.py:139-140`). Reviewers default to `owner` (`bootstrap/settings.py:392`) [L run b].
- **Human Gate node** [T, L run k with a disclosed service reviewer]: `mc.human_gate.v1` child workflow,
  wired in Stage Graph (`workflows/stagegraph.py:1154-1214`) and Goal Loop (`goal_directed.py:598`);
  manifests can express only approve/deny (no `request_changes`, remediation target, default answer);
  no `missionctl human-task` command.
- **Mutating a running run** [D]: revision tables exist but only `insert_admitted_run` writes them; no
  command can change model, MCP, skills or stages on a live run. The only real path is a semantic fork
  (`domain/policies/forks.py:801-822`), which produces a new run.

## 7. Coordinator peek and act

- Surfaces: operator MCP (`mission_run_inspect`, `mission_run_transcript`, `mission_command_send`,
  `mission_run_fork`, `coordinator_inbox_*`), `missionctl run inspect|transcript|frames|command|fork|wait`,
  HTTP run-control `RunInspection`, Socket.IO stream (ADR 0036, proposed).
- **No unified peek**: current stage/unit, budget, effects and async children are only in HTTP
  `RunInspection` (`application/.../runtime_inspection.py:124-169`); `mc.inspection.v1` lacks them;
  lineage is Socket.IO-only, and Socket.IO is not on the default or cloud entrypoint
  (`Makefile:183`, `deployments/cloud_runtime/Dockerfile:24`).
- **No mid-run file read**; transcript `--full` returns 501.
- **An agent inside a run cannot coordinate**: the operator bearer never enters an environment
  (ADR 0049); only passive W5 `prompt_mode` delivery of wakes into a coordinator run's mailbox exists [T].
- Live findings: `missionctl wait` does not refresh tokens [L run a]; a second `review_required` did
  not wake a fresh wait [L run e, cause unconfirmed]; usage `unknown` on every run [L].
- *2026-10-20.* The peek-and-wake loop is now evidenced on two lanes and on both schedulers: MR-01,
  MR-02, MR-11 and MR-12 [L]. In each, the wait was registered before start; the harness was woken
  by `review_required` and then `terminal_result` and acknowledged; and inspect + transcript peeks
  ran while the run was active (5 to 14 per run). Two new findings: `missionctl` has a fixed 30 s HTTP
  timeout that Cloud preflight exceeds (`interfaces/cli/main.py:1027`); and frame bodies are 2 KB
  excerpts, so the agent's advertised tool list cannot be read through Mission Control.

## 8. Linked workflows

Chains compile to linked missions released by the outbox (ADR 0029). State crosses only as a
`chain_link` Context Packet (artifacts, acceptance, checkpoint refs, transcript instruction); "nothing
from a supplier's workspace is restored" (`application/chains/packet.py:1-10`). The packet hard-codes
`LaneFileSupport(writable_workspace=True)` for any consumer (`packet.py:331`) — untested for hosted
consumers such as `claude_managed` or `codex_agents`. A Goal Loop hands off only at terminal
completion (`workflows/goal_directed.py:659-688`).

## 10. Provider facts the owner asked about

- **OpenAI**: Mission Control supports only the hosted **OpenAI Agents API** (sessions running the
  Codex harness) through its own `httpx` client with `OpenAI-Beta: agents=v1`
  (`adapters/openai_agents/client.py:35-117`). The `openai-agents` Python package is **not** a
  dependency (absent from `pyproject.toml`/`uv.lock`); `openai` 2.44 is used only for embeddings and
  LangSmith. The `openai_sdk: 3.29.0` labels in describe are smoke-script provenance, not runtime.
- **Claude and Codex "cloud"**: `claude_cloud` and `codex_cloud` have **no adapter** and no public
  control API (feasibility "Outcome 3"); only describe stubs and projection renderers exist. "Claude
  cloud" with real control today means `claude_managed`; "Codex cloud" with real control means
  `codex_agents`.
- **Deep Agents** model factory maps every model to `OpenAIExactModelFactory`
  (`adapters/temporal/deployment_composition.py:403-405`).
