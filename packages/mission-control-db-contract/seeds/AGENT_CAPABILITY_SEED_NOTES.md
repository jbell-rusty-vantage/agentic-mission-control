# Agent-capability seed notes (FT-A6)

and `mc.app.ai-engineer.agent-capabilities@1.0.0` are generated by `generate_catalog_seeds.py` from
`agent_capabilities.py` and `tests/fixtures/mcp/<id>.tools.json`. They require migration 0025.

## Tool lists

The `tools/list` fixtures are transcribed from `docs/specs/archive/fast-track-2026-10/research/seed-capabilities-and-formats.md`
(`capture_method: transcribed`); no server was run in this wave. Input schemas are recorded as
`{"type": "object"}` until a live capture. Re-capture each server once with
`scripts/capture_mcp_tool_snapshot.py`, replace the fixture, regenerate the bundles (new seed
version if 1.0.0 was applied) and run `make seeds-validate`. That holds for the six 1.0.0 servers
only: the three servers of 1.1.0 below are `capture_method: captured`.

- **The tool lists are captured, not transcribed** (`capture_method: captured`; each fixture's `capture`
  object records the command, the version the server reported, the tool count and that no credential
  was set). Each MCP Tool row carries the server's own description and input schema.
- `mcp.github` needs no allowlist: read-only is the server's own mode, and it lists no write tool in it.
  The OCI image of the tag was not run; the list came from the release binary of the same tag.
- `mcp.knowledge-capture` withholds every tool that writes knowledge or needs an issuer credential
  (`ingest_*`, `knowledge_operation_*`, `knowledge_receipt_get`, `knowledge_describe`), the direct
  database reads (`db_*`; the recorded read is the governed `tool.knowledge-read-intent`), and the
  host-side state and file tools (`checkpoint_*`, `artifact_get`, `schema_materialize`,
  `source_prepare_captured`). It is `unqualified` on every worker-hosted profile and `unsupported` on
  cursor_cloud: the executor lists all 40 tools and no lane narrows a server's list to an allowlist, so
  a manifest pin is refused at compile until a lane qualifies. What has to be built first is in the
  [provider note](../../../docs/specs/provider-consolidation-2026-10/providers/research-capabilities/RESEARCH-CAPABILITIES-SURFACE-2026-11-16.md#capture-path).
- `plugin.code-research` is a sibling of `plugin.web-research`, not its next revision: a mission that
  only searches the web keeps needing only the Tavily and Firecrawl secrets, and a plugin that changes
  membership under `@latest` would change what running missions mount. It sits in the common bundle
  because both members do. The Deep Agents lane has no launch binding for a plugin a node selects
  (`adapters/deep_agents/compile.py`), so a Deep Agents mission pins the two servers under
  `environment.capabilities`; the plugin serves the file lanes and a child's seeds.
- No arXiv server is seeded (see the rejected candidates and the provider note).

# Agent-skill seed notes (FT-A7)

Seed bundles `mc.app.biotech.agent-skills@1.0.0` and `mc.app.ai-engineer.agent-skills@1.0.0`
are generated by `generate_catalog_seeds.py` from `agent_skills.py`. There is no common
agent-skills bundle: an `mc.capability_bundle_manifest.v1` names its application, so the same
bytes have one manifest digest and one object prefix
(`<application>/<kind>/<id>/<version>/<manifest sha256>`) per application. Each bundle depends on
`mc.catalog.agent-capabilities` and its application's `agent-capabilities` (plugin members), and
requires migration 0025.

| `skill.biomcp` 0.9.1 | biotech | `biomcp skill install` of `biomcp-cli` 0.9.1, captured on Linux (the installer refuses Windows: "Atomic skill installation is unsupported on this platform"); `.biomcp-skill.json` carries the capture's `installed_at` |

Captures live under `tests/fixtures/skills/` with `-text` git attributes (no line-ending
conversion) and are excluded from the whitespace hooks.

- **Conflict to resolve with the owner:** upstream edgartools 5.61.1 `SKILL.md` declares
  `name: EdgarTools`, which breaks the Agent Skills name rule (lowercase, equals the directory).
  The bundle stays verbatim (Mission Control adds nothing inside a third-party bundle) and the
  catalog's `skill_name` is the directory name `edgartools`. Hosts that validate the frontmatter
  name strictly may reject it.
- Bytes reach the bucket only through `scripts/seeds_publish_bundles.py --target <app> --storage
  supabase` (publisher credential, never the service key); nothing was uploaded to a live bucket.
- `skill.mission-control-coordinator` (frozen `mc.catalog.approved-assets@1.0.0`) is no live
  skill since 2026-11-16: its source is the archive `bundle-sources/approved-assets-1.0.0/` and
  no later seed version publishes it (`approved-assets@1.0.3` holds the router manifest only).
  Its catalog row is not retired: the legacy coordinator composition still resolves it and
  refuses a retired binding (`bootstrap/coordinator_composition.py`), and a seed cannot retire
  a row (it never moves `asset_version.status`). Retire it with the catalog's retire operation
  together with the consumer change (CS-D12).

### Imported method skills (2026-11-16, `mc.app.<app>.agent-skills@1.0.5`)

`bundle-sources/imported/<source>/<commit7>/<skill>/`, recorded in `imported/IMPORTS.json`
(`scripts/skills_import.py`). `source_provenance` is `source: belllabs`, `upstream_identity`
the minted slug `<source>/<skill>`, `upstream_version` the skill's declared `metadata.version`
or the commit's UTC date, followed by `-<commit7>`, and `commit_digest` the commit. The catalog
description is the frontmatter description on one line.
